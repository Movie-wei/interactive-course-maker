# 交互课程制作法（interactive-course-maker）

把一套经过 4 周实战验证（本体工程 × 医保导办场景，4 份课程、约 270 项断言全过）的个人学习法固化为可复用流程：**对任意新领域，先用对话与用户共创出真正属于用户的内容，再把它装配成单文件、离线、闯关式、带自检与报告页的交互 HTML 课程，并按验收真实产品的标准验证后才交付。**

## 0. 触发规则

- **仅手动触发**：只在用户明确点名（「用课程制作法」「做交互课」「interactive-course-maker」等）时加载。未点名时不得自行加载，即使任务看起来是学习新知识或写 HTML。
- 加载后且目标领域不是当前已有课程时，按本流程从阶段 0 开始。
- 用户只是提问、查记忆、批改已有作业时，不加载本技能。
- 目标目录已有相关课程与 `开发说明.md` 时，这是接力：先读它们了解背景与约定，再继续，不重复已完成的工作，沿用既有 localStorage 键与样式。

## 1. 两条铁律（所有阶段必须遵守）

1. **内容必须由用户共创出来。** 禁止把参考资料原文直接甩给用户填空；你只提供引导问题、形式化整理与结构示意。参考写法只在用户确实卡住时作为「结构示意」出现，且要与正式填写分开展示。
2. **领域事实与通用方法论分离。** 通用方法论（概念、方法、步骤）可以自信地讲；领域事实（法规、费率、流程、政策、专业意见）要么先检索权威来源验证，要么标注「教学示意，正式业务以权威部门/来源为准」。正式业务结论一律不写死。

## 2. 总流程（六个阶段，顺序执行，不许跳）

| 阶段 | 名称 | 产出 |
|---|---|---|
| 0 | 摸底与目标 | 领域名、贯穿场景、周计划骨架 |
| A | 内容共创（引导协议） | 逐栏定稿的学习内容 |
| B | 课程设计 | 章节清单 + 每章题型映射 |
| C | 工程化装配 | 单文件 HTML |
| D | 验证 | 全部断言通过 + 截图存档 |
| E | 交付入库 | README/开发说明/进度总账同步 + git 提交 |

## 3. 阶段 0：摸底与目标

一次只问一个问题，按序推进：

1. 想学的领域是什么？
2. 学完要能独立做成什么事？（可验证成果，不是"了解/掌握"这种虚词）
3. 有没有一个真实、具体的贯穿场景？（像「在广州办理医保参保」之于本体工程那样）
4. 当前水平：零基础 / 入门 / 有经验？
5. 有哪些可用参考资料与权威来源？
6. 每周可投入多少时间？计划学几周？

输出：`领域名`、`贯穿场景`（一句话）、`周计划骨架`（每周 = 一个可验证成果，参考 README「未来 14 天执行表」的两列格式：任务 → 可验证成果）。

## 4. 阶段 A：内容共创（引导协议，本方法的核心）

**任何内容都不得代填或跳过此阶段。** 参考示例：第 2 周「最小场景范围」七栏即用此法逐栏共创定稿。

### A1 节奏规则

- 每轮只抛一个小问题，用户作答后才进入下一轮。
- 用户先用大白话回答；你负责确认、追问，并整理成可填入的正式句式。
- 一轮只推进一个决策点。发现冲突（如上一栏定稿与当前回答矛盾）时，把选项 A/B 摆给用户选，**不许擅自改**。
- 收集到的每条内容立即标注来源或状态：`用户自拟` / `默认值（可改）` / `待确认`。
- 全部规则与数据标注「教学示意，非正式结论」。

### A2 引导问题库（按序推进，可裁剪）

1. **目标**：学完最想做成什么事？
2. **场景**：找一个真实具体的贯穿场景。
3. **范围界定（纳入 vs 不纳入）**：先问「别人可能顺带提的要求，哪些你不做」，再问「你要做的核心是什么」；冲突暴露时让用户决策。纳入范围建议按五行整理：人群 / 事项 / 环节 / 数据 / 应用形态。
4. **关键未知**：「假设明天能和该领域行家聊 10 分钟，最想问哪三件事？」——每一条补上「由谁确认」。
5. **任务拆解**：把目标拆成可验证子任务，映射到每周。
6. **陷阱与难点**：让用户说出最容易出错、最容易忘的地方，做成找错题/判断题素材。
7. **汇报与自评**：若课程目标是「向人讲清楚 / 汇报」，加汇报演练与自评章。

### A3 自检规则

- 每个开放题/表单都要有「结构自检 + 参考答案」，并如实标注「自检不等于评分」。
- 自检只做关键词与数量检查（字数阈值、必填字段、条目数、命名长度如「场景名 ≤ N 字」），不做语义评分。
- 阈值在页面上一处声明（如 `const MIN_CHARS = 450`），测试断言与页面口径必须一致。

## 5. 阶段 B：课程设计

- 章节 = 学习目标的有序分解；每章 1 个主交互题型 + 完成/锁定机制。
- 首页：课程说明、章节导航、进度、重置（带二次确认）、版本与免责标注。
- 报告页：可复制的学习摘要，格式全课程一致，供对话批改。
- 题型映射（组件库详见 `references/交互组件库.md`）：

| 学习目标 | 主题型 |
|---|---|
| 概念记忆 | 翻卡（背面定义 17px 加粗近黑，正面白底） |
| 结构/关系理解 | 内联 SVG 图解（带箭头、节点文字不加描边、文字宽度须适框、viewBox 等比缩放） |
| 判断/辨析 | 即时测验（逐题解析）或找错题（按错误分组判定命中） |
| 流程/优先级 | 排序题（上移/下移，不做真随机） |
| 场景演练 | 情景闯关（即时反馈 + 解锁条件可见 + 重玩） |
| 与人打交道 | 模拟对话（选项轮换避免「最好总在第一个」） |
| 表达 | 开放题（结构自检 + 参考答案）+ 汇报稿字数自检 |
| 综合评估 | 自评（必须配证据清单；高自评而证据不足一半时提示可能高估；标「不是正式成绩」） |

## 6. 阶段 C：工程化装配

**技术规格（全部硬性）：**

- 单文件离线 HTML：无外部 http/https 引用、无 CDN、无远程字体、无外图；CSS/JS 全内联。
- 配色：背景 `#f5f7fb`，卡片白，主色 `#496fe6`，辅助薄荷 `#26a789`，提醒琥珀 `#d68a24`。
- **字号分层（硬性，按层配字重，禁止越级）**：
  - 正文/题干/选项/反馈/卡片解释 ≥16px，常规字重（400）；
  - 辅助文字（muted/提示/标签/导航）≥15px，颜色不浅于 `#4f5d73`；
  - 标题 ≥20px（h3）、章节标题 ≥22px（h2）、课程标题 ≥26px（h1）；
  - 关键术语/定义首词 17px 加粗近黑，解释文字 16px 常规——**同一卡片内只允许首词或标题加粗，禁止整段加粗**；
  - SVG 内文字：节点标题 ≥14px，辅助说明 ≥12px（viewBox 缩放后仍可读）。
- **间距规范（硬性，统一节奏）**：行高 1.65~1.75；卡片内边距 22~26px、卡片间距 14~18px；段落间距 10~14px；标题上下留白 ≥8px；列表项间距 ≥6px。
- **布局（硬性）**：左侧章节导航 + 主区单列 + 卡片圆角 22px；窄屏导航横向滚动，内容区 `minmax(0,1fr)`；**卡片/方框不得重叠**（检查所有盒子的 boundingRect 两两不相交，SVG 内节点矩形同理）。
- 动画：只用淡入和翻卡；支持 `prefers-reduced-motion`。
- 存储：localStorage，键名 `{领域拼音}Week{N}ProgressV1`；重置带二次确认。
- 锁定态按钮必须看得出来（变灰 + 写明解锁条件如「还剩 N 关」），禁止用原生 `disabled` 吞掉点击；点击时给出提示。
- 动态创建的元素写完立刻挂载（appendChild）；状态变化统一调用渲染函数，不零散改节点。
- 需要宽高/定位的容器显式 `display:block/flex/grid` 并给固定高度（翻卡类组件）。

**构建管线：**

- 一律用 **Node 脚本（.js）**，不用 .ps1：Windows PowerShell 5.1 会把无 BOM 的 UTF-8 当 ANSI 读，中文文件名/内容乱码；Node 读写 UTF-8 无此问题。用 `path.resolve` 拼路径，按前缀匹配中文文件名。
- 装配方式：`CSS / body（章节内容）/ data（数据与答案）/ logic（脚本）` 四部分分别成文件，`build.js` 拼成单文件。
- v2 演进：定义「课程规格 JSON」（领域/周/章/每章交互块），写渲染器由规格直接出 HTML，新课程 = 填数据而非写代码。
- 修改 HTML 优先用 `edit` 逐处替换，每次替换后立刻 `node --check` 语法检查。

## 7. 阶段 D：验证（出厂前必须全过）

**静态检查：**
- [ ] `node --check` 语法通过
- [ ] 无外部引用（搜 `http://`、`https://`）
- [ ] 写死的章节数/统计与首页、报告页一致

**交互验证（CDP 真点，驱动脚本见 `references/验证脚本模板.js`）：**
- [ ] 每章至少一次真点击：导航、选项、提交、重玩、重置
- [ ] 故意答错/不答：锁定、拒绝、提示全部可见且不改分
- [ ] 刷新恢复：localStorage 预置必须在页面脚本之前写入（`Page.addScriptToEvaluateOnNewDocument`），该项单独测
- [ ] 用用户真实答案测自检逻辑（不只测编造的好答案）
- [ ] 断言「可点击元素数量 > 0」，防止创建未挂载

**视觉验证（逐项脚本量化，不靠目视猜测）：**
- [ ] 逐页截图 + 目视检查，**禁止只看首页**（历史事故：错乱发生在第 2 页）
- [ ] 512px 与 390px 窄屏：`scrollWidth ≤ innerWidth`（脚本量，不靠猜；无头最小视口约 512px）
- [ ] 截图前等淡入动画 ≥400ms，否则画面发灰
- [ ] **字号断言**：脚本遍历正文容器，`getComputedStyle` 检查正文 ≥16px、辅助 ≥15px、标题 ≥20px；SVG 内 `<text>` 无 <12px 的
- [ ] **加粗占比断言**：正文段落整段加粗（`<strong>`/`font-weight≥700` 覆盖整段）数量 = 0，只允许术语/标题/关键词加粗
- [ ] **重叠断言**：每页所有可见卡片/方框 `getBoundingClientRect` 两两不相交（可忽略嵌套包含关系，检查同级兄弟元素）；SVG 节点矩形两两不相交、全部在 viewBox 内
- [ ] **间距断言**：相邻卡片垂直间距 ≥12px（脚本量上下兄弟元素间距）；行高 ≥1.6
- [ ] **SVG 文字适框断言**：每个 `<text>` 用 `getBBox()` 量宽度，与所在节点框比较两侧留白 ≥12px；桌面和 390px 窄屏各测一次（只测节点矩形不够，文字会超出矩形）
- [ ] **SVG 文字清晰断言**：每个 `<text>` 的 `stroke` 为 `none`；深底白字节点截图后统计抗锯齿过渡像素占比 <10%

## 8. 阶段 E：交付入库

- 临时文件（截图、`.tmp*`、`verify*.js`）全部清理，`git status` 干净才算完成。
- 同步更新：README（档案清单 + 推荐入口）、开发说明（需求/日志/决策/已知问题）、学习进度总账。
- 提交信息规范：`feat: 新增{主题}交互课`。
- 免责：凡领域事实标「教学示意，正式业务以权威部门为准」。

## 9. 领域事实安全规则（硬性）

1. 区分「通用方法论」（可自信讲）与「领域事实」（法规、费率、流程、政策、专业意见）。
2. 领域事实处理优先级：检索权威来源验证 → 验证不了标「待确认」→ 教学场景统一标「示意」。
3. 法律、医疗、财务、安全等敏感领域：课程显著声明「学习材料，不构成专业意见」，风险由用户自担。
4. 用户自拟内容与权威来源冲突时，把冲突摆给用户，由用户决策并记录到开发说明。

## 10. 历史踩坑（完整版在 `references/踩坑清单.md`，每次开工前过一遍）

| 坑 | 规则 |
|---|---|
| 翻卡内层 span 致宽高失效 | 容器显式 block/flex/grid + 固定高度 |
| 灰字 14px 淡底看不清 | 正文 ≥16px，关键定义近黑加粗 |
| div+旋转线拼图对不齐 | 连线图一律内联 SVG 带箭头 |
| disabled 按钮吞点击 | 锁定态可见 + 点击有提示 |
| 开放题无反馈 | 每个输入必有提交与反馈；自检 + 参考答案，标注「不是评分」 |
| 通关后不显示重玩 | 状态变化统一渲染 |
| 动态 button 未挂载 | 创建即 appendChild |
| 找错题跨行判定/计分/显示口径不一 | 按错误分组判定，一处修处处生效 |
| 状态键与 DOM id 同名覆盖 | 不同后缀或集中声明 |
| 同类题型复制粘贴漏改 | 抽通用函数（如 `mcq()`） |
| **辅助文字 13~15px 太小看不清** | 字号分层硬性：正文 ≥16、辅助 ≥15、标题 ≥20；SVG 内文字 ≥12 |
| **卡片/方框重叠** | 布局检查所有盒子 boundingRect 两两不相交；SVG 节点矩形全在 viewBox 内且不重叠 |
| **SVG 文字模糊 / 超出方框** | 节点文字不加描边；`getBBox()` 量文字宽度，两侧留白 ≥12px；副标题按 `(框宽-24)/字号` 控制字数 |
| **整段加粗无主次** | 只允许术语/标题/关键词加粗；定义 = 17px 术语加粗 + 16px 解释常规 |
| **间距无节奏** | 统一间距规范（行高 1.65~1.75、卡片内边距 22~26、段落 10~14）并脚本断言 |
| **只看首页漏测第 2 页** | 逐页截图 + 脚本量化（字号/重叠/间距），不靠目视 |

## 11. 一次会话的最小形态（验收本技能是否有效）

用户说：**「用课程制作法学习《XX》领域，目标是我学完能 YY」**

预期行为：
1. 阶段 0 逐个抛出摸底问题（每轮一个）；
2. 阶段 A 用 A2 问题库逐栏共创，全程不代填、不甩参考原文；
3. 阶段 B/C 产出单文件 HTML（全内联、无外部引用）；
4. 阶段 D 真点击全过 + 逐页截图目视 + 窄屏无溢出；
5. 阶段 E 清理临时文件、同步文档、git 提交。
