# 踩坑清单（完整版）

> 全部来自实战：第 1 周用户反馈的 5 个问题 + 工具坑 + 第 3/4 周新坑。开工前读一遍，交付前对照 `验证清单.md` 逐条打勾。

## 一、已发生的问题与根因

| # | 现象 | 根因 | 预防规则 |
|---|---|---|---|
| 1 | 业务对象层整页错乱，翻卡变竖排窄条 | 翻卡内层用 `span`（行内元素），宽高百分比失效 | 凡需设宽高、定位的容器一律显式 `display:block/flex/grid`；翻卡类组件给固定高度 |
| 2 | 翻卡背面定义文字看不清 | 灰字、14px、细体放淡蓝底，对比度不够 | 正文 ≥16px；关键定义近黑加粗；辅助灰不浅于 `#4f5d73`；示例白底标签 |
| 3 | 关系图画不对（线没对准、无箭头） | 绝对定位 div + 旋转线拼图 | 连线图一律内联 SVG，带箭头；文字直接放在节点填充框内，不加描边（见 #16）；窄屏靠 `viewBox` 等比缩放 |
| 4 | 「完成闯关」按钮点了没反应 | 按钮 `disabled` 但样子像可点；点击无提示 | 锁定态必须看得出来（变灰 + 写清解锁条件，如「还剩 N 关」）；点击给提示；不用原生 `disabled` 吞点击 |
| 5 | 开放题提交后无反馈 | 页面只存答案，没说清也没处理 | 每个输入框必有提交动作与反馈；做不到自动评分就给「结构自检 + 参考答案」并标注「不是评分」 |
| 6 | 首次通关后不显示「重玩」 | 完成态只改了按钮，没重渲染界面 | 状态变化后统一调用渲染函数，不零散改节点 |
| 7 | 选项按钮创建后点不了 | 创建了 `button` 没 `appendChild` | 动态创建元素写完立刻挂载；测试断言「可点击元素数量 > 0」 |
| 8 | 找错题一个错误占两行时，只选一行让另一行显示「漏掉」 | 按「行」判定命中，计分按「错误」判定 | 判定、显示、计分三处口径一致：按错误分组判定，同组任一行选中即命中 |
| 9 | 分数键与显示元素同名互相覆盖 | 数据键 `gjScore` 与元素 id `gjScore` 重名 | 状态键与 DOM id 不同后缀（如 `*Txt`），或集中在配置里声明 |
| 10 | 多个选择题章节各写渲染函数，漏掉锁定与反馈 | 复制粘贴 | 同类题型抽通用函数（如 `mcq`），一处修处处生效 |
| 11 | 辅助文字 13~15px 太小、看不清 | 只用一条「正文 ≥16px」，没约束辅助层 | 字号分层硬性：正文 ≥16、辅助 ≥15、标题 ≥20、SVG ≥12；按层配字重 |
| 12 | 卡片/方框重叠、布局混乱 | 未检查盒子几何关系；SVG 节点矩形越界或相交 | 脚本断言：每页可见盒子 boundingRect 两两不相交；SVG 节点全在 viewBox 内且不重叠 |
| 13 | 大段内容整段加粗、看不清主次 | 定义/解释整段用 17px 700 | 只允许术语/标题/关键词加粗；定义 = 17px 术语 + 16px 解释常规 |
| 14 | 内容间距无节奏、看着挤 | 没有统一间距规范 | 间距硬性：行高 1.65~1.75、卡片内边距 22~26、段落 10~14、卡片间距 14~18；脚本断言相邻卡片间距 ≥12 |
| 15 | 只看首页截图，漏掉第 2 页的错乱 | 验收只截首页 | 逐页截图 + 脚本量化（字号/重叠/间距/窄屏），不靠目视 |
| 16 | SVG 根节点白字发糊 | 所有 SVG 文字统一套白色描边（`paint-order:stroke; stroke:white`），白字落在蓝底上，白描边把笔画糊成一团 | SVG 节点文字一律 `stroke="none"`；描边只给压在无底色线条/图片上的独立标注，且描边色必须与文字色反差 |
| 17 | SVG 节点副标题超出方框 | 只断言节点矩形不越界、不重叠，没测文字实际宽度；25 字副标题 13px 约 325px > 280px 方框 | 脚本用 `getBBox()` 量每个 `<text>` 宽度，要求两侧各留 ≥12px；写数据时副标题 ≤ `(框宽-24)/字号` 个字（280 宽、13px ≈ 19 字），超了就缩写，细节放点击后的解释里 |

## 二、验收方法的教训

1. **必须逐页截图并目视检查，不能只看首页。** 第 1 周错乱发生在第 2 页，只截了首页就漏了。
2. **交互必须用脚本真点一遍**：导航、翻卡、选择、提交、重玩、刷新恢复。只测「渲染成功」不够。
3. **用户给的真实答案当测试数据**，不要只用编造的「好答案」。
4. **无头浏览器最小视口约 512px**，窄屏溢出要用脚本量 `scrollWidth`，不能只看截图。
5. **刷新恢复要单独测**，且预置数据要在页面脚本之前写入（`Page.addScriptToEvaluateOnNewDocument`）。

## 三、工具使用的教训（本环境）

1. 不要在 `pwsh -Command` 里拼含引号、中文、正则的长字符串，容易转义出错且静默失败。
2. 复杂检查写成脚本文件再执行。**首选 Node 脚本（`.js`）**：Windows PowerShell 5.1 会把无 BOM 的 UTF-8 当本地编码读，中文文件名乱码；Node 读写 UTF-8 无此问题。用 `path.resolve(__dirname, '..')` 拼路径，按前缀（`startsWith('第3周')`）找中文文件名。
2a. 本环境可能没有 `pwsh` 别名，脚本里别调用 `pwsh`；直接用 `node`。
2b. 无头浏览器验证零依赖：Edge 加 `--remote-debugging-port`，Node 24 自带 `WebSocket` 连 CDP，`Runtime.evaluate` 真点击读状态，`Page.captureScreenshot` 截图，`Emulation.setDeviceMetricsOverride` 设窄屏，`Page.addScriptToEvaluateOnNewDocument` 预置 localStorage。截图前等淡入 ≥400ms。
2c. 子进程不能通过管道捕获输出（`stdio:'pipe'` 在本环境 EPERM），启动浏览器用 `stdio:'ignore'`。
3. 脚本名被删除后 `write` 工具会提示「文件不存在」，换新文件名即可。
4. 修改 HTML 优先 `edit` 逐处替换，每次替换后立刻 `node --check`。
5. 临时文件（截图、`.tmp*`、`.verify*`）每轮结束必须清理，提交前 `git status` 确认干净。
6. 改动前先 `read` 文件，`edit` 才会成功。
