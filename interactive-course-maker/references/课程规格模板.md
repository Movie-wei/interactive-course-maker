# 课程规格模板（v2 演进，可选）

> v1 用四组件手工装配；v2 的目标是「填数据而非写代码」：一份规格 JSON + 一个渲染器直接出单文件 HTML。
> 本文件是规格骨架与字段说明。渲染器实现前，本模板也可当作章节设计清单使用。

```json
{
  "domain": "ontology",
  "storageKeyPrefix": "ontologyWeek{N}ProgressV1",
  "title": "第 N 周 课程主题",
  "scenario": "贯穿场景一句话（如：灵活就业人员在广州办理医保参保）",
  "disclaimer": "教学示意，正式业务以权威部门为准",
  "weeks": [
    {
      "week": 1,
      "goal": "本周围绕的『可验证成果』（学完能独立做成什么）",
      "chapters": [
        {
          "id": "ch1",
          "title": "章节名",
          "type": "gate | flip | svg | mcq | sort | find | dialogue | open | report | selfcheck | scope",
          "data": {}
        }
      ]
    }
  ],
  "report": {
    "sections": ["章节完成", "各题得分", "开放题答案", "自评"],
    "copyable": true
  }
}
```

## 字段说明

- `domain`：领域拼音前缀，只用于 localStorage 键名（`ontologyWeek2ProgressV1`），保持与已有课程兼容。
- `weeks[].goal`：来自阶段 0 的「可验证成果」，每章都服务这个目标；目标写虚词（了解/掌握）视为不合格。
- `chapters[].type`：对应 `交互组件库.md` 的题型，一题一个主题型；不要一章堆多种题型。
- `chapters[].data`：按题型填内容——选择题给题干+选项+解析+正确答案；找错题给样本与错误清单（含跨行分组）；排序题给条目与正确顺序；对话题给分支与轮换规则；开放题给模板+参考答案+自检阈值。

## 自检阈值声明约定

- 阈值统一放规格顶层或章节 `data` 的 `check` 字段（如 `{ "minChars": 450, "required": ["关键词A", "关键词B"] }`）。
- 渲染器必须把同一阈值同时用于页面显示与测试断言，杜绝「页面 450、测试 600」这类口径不一致。

## localStorage 键约定

- 每份课程独立键：`{domain}Week{N}ProgressV1`；键里带课程与版本，互不污染。
- 内容至少含：`done`（完成的章节 id 数组）、`answers`（各题答案）、`score`（测验分）、`self`（自评）。

## 与引导共创的衔接

- 规格不是先写后共创，而是**共创一段、落一段**：阶段 A 每定稿一栏，就把结果填进规格对应字段；全部定稿后规格自然完整，再进阶段 C 装配。
